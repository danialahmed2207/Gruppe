# Scrum Basics

> Core concepts of the Scrum framework for IT project delivery.

---

## The Scrum Framework

Scrum is an agile framework for managing complex work. It emphasizes iterative progress, team collaboration, and continuous improvement.

### Roles

| Role | Responsibility |
|------|---------------|
| **Product Owner** | Defines what to build, prioritizes the backlog |
| **Scrum Master** | Facilitates the process, removes blockers |
| **Development Team** | Delivers increments of working software/systems |

### Artifacts

| Artifact | Purpose |
|----------|---------|
| **Product Backlog** | Prioritized list of all desired work |
| **Sprint Backlog** | Tasks selected for the current sprint |
| **Increment** | Potentially releasable result of a sprint |

### Ceremonies

| Ceremony | Frequency | Duration (2-week sprint) | Purpose |
|----------|-----------|--------------------------|---------|
| Sprint Planning | Per sprint | 2–4 hours | Plan sprint goals and tasks |
| Daily Standup | Daily | 15 minutes | Sync on progress and blockers |
| Sprint Review | Per sprint | 1–2 hours | Demo work to stakeholders |
| Sprint Retrospective | Per sprint | 1–1.5 hours | Reflect and improve process |

### Sprint Cycle

```
Sprint Planning → [Daily Standups] → Sprint Review → Retrospective
                        ↓
                   Sprint Backlog
                        ↓
                    Increment
```

## Scrum in IT Operations

While Scrum is traditionally used for software development, IT operations teams can adapt it for:

- **Infrastructure sprints**: Deploying new servers, networks, or cloud resources
- **Automation backlogs**: Building scripts and tooling iteratively
- **Incident response improvements**: Treating process enhancements as backlog items

### Practical Tips

- Keep sprints short (1–2 weeks) when learning
- Make backlog items actionable and specific
- Track blockers visibly on the board
- Use retrospectives to improve the process, not blame individuals
